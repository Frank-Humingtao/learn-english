## Question

词汇量测试、卡片学习、进度查看（以及推荐入口）这几个界面应该长什么样、怎么流转？做一个粗略原型来对照，确认第一版 App 的屏幕清单与核心交互。


### 来自「进度汇报 issue 的格式」的补充

- 推荐和阅读已移出系统范围，App 里不做「推荐入口」。屏幕清单只含词汇量测试、卡片学习、进度查看。

### 来自「仓库作为真相源还是需要后端」的补充

- 界面要常驻显示「未同步 N 条」，令牌失效或过期时要有明确的错误提示（不能静默停止同步）；需要一个粘贴 PAT 的设置入口。
- 原型阶段实测：`createCommitOnBranch` 的 `expectedHeadOid` 与分支 head 不一致时返回什么错误。

## Answer

原型：[prototypes/11-app-screens/index.html](../prototypes/11-app-screens/index.html)（双击打开，`?variant=A|B|C` 切换三种首页；B、C 未被选中，只作参考保留）。

学习者的选择：
- **导航结构用 A：底部标签栏**（像墨墨），四个标签「学习 / 测试 / 进度 / 设置」。不选「今日一条龙」（B），也不选「看板首页」（C）。
- **卡片评分用 4 档**：忘了 / 模糊 / 想起 / 太简单，对应 FSRS 的 Again / Hard / Good / Easy，按钮下方显示下次间隔。
- **同步状态平时隐藏**：全部已同步时什么都不显示；有未同步记录时，导航栏右上角出现「未同步 N 条」（点一下立即同步）；令牌出错时另加红条（见下）。

第一版屏幕清单：
1. **首次启动**（三步）：欢迎页 → 粘贴 GitHub fine-grained PAT（可以跳过，稍后在设置里补）→ 基线测试介绍（约 30 分钟，可以中途退出，下次从断点继续）。
2. **学习**标签：今天到期的卡片数和「开始复习」按钮；今天还没做短测时，下面有一条提示，点它去测试。新卡的数量和来源由「Target 词的选取与排序」决定。
3. **测试**标签：今日短测的入口（今天已测过也能再测一次），以及上次的结果。
4. **测试流程**（全屏，基线测试和短测共用）：Yes/No 题（「认识 / 不认识」，混入假词）→ 中文四选一释义核验（带「不认识」选项）→ 结果页（估计词汇量及范围、较上次的变化、新发现的 Target 词数、抽查已掌握词的对错、假词误认数）。左上角 ✕ 可以退出。
5. **卡片复习**（全屏）：正面是词、音标和发音；点一下翻面，显示英文释义、例句和中文释义；底部 4 个评分按钮；全部做完后显示完成页。
6. **进度**标签：估计词汇量（word family）、误差和曲线；三类词（已掌握 / 正好该学 / 太遥远）的条形图；各词频段的掌握率；连续学习天数、最近测试日期；外链到公开看板和最新的 Progress Report。数字由本机重算，页面上注明公开看板会稍有滞后。
7. **设置**标签：同步状态（状态、未同步条数、上次成功时间、仓库名）和「立即同步」按钮；粘贴并替换 PAT（显示令牌有效期）；「重做基线测试」。

同步与报错的交互：
- 自动同步发生在一次测试或复习结束时，以及 App 回到前台时。每作答一题就记一条本地 Observation，「未同步 N 条」随之增加。
- 令牌未设置、过期或被撤销（401）时，每个页面顶部常驻红条，写明原因，并说明「记录都还在本机」；点红条进入设置页。换好令牌后自动补交。
- 断网不算错误，只显示灰色的「离线中，联网后自动同步」。

实现细节（agent 决定）：
- `createCommitOnBranch` 的 `expectedHeadOid` 冲突时返回什么错误，需要真实令牌和仓库才能测，移到实现阶段（记在地图「技术栈细节」里）。处理方式沿用「仓库作为真相源还是需要后端」的结论：拉取最新 head 后重试。
- 原型没有按 prototype 技能的要求提交到废弃分支：本仓库的提交由父会话负责，原型文件暂时放在 `.scratch/` 下。
