# 选词规划 skill 的设计

Type: grilling
Status: resolved
Assignee: humingtao
Blocked by: 12
Part of: ../map.md

## Question

「Target 词的选取与排序」定下：选词由一个新写的 Claude skill `word-plan`（选词规划）完成，在 Claude 桌面 App 里每天定时跑一次，写出 Study Plan 到 `english-data/plan/`。这个 skill 具体怎么设计？

- 它读哪些输入（测试与复习记录、`words.tsv`/学习档案、设置、「想学」记录、上一份计划），读多少历史才够又不撑爆上下文。
- 选词与排序的判断准则写成什么样的提示：似懂非懂、词频、复习积压、顽固词、手动加词的优先级。
- 选词说明的写法与质量要求（长度、中英、不得编造词义），以及与卡片主内容（词典释义、例句）的分工。
- `focus_targets` 的挑选思路。
- 输出文件的校验：lemma 必须在词表里、条数不超上限、JSON 合法；不合格时怎么办。
- 本机定时任务的配置（需要 Mac 开机、本地 clone `english-data`、提交权限），以及运行失败时学习者怎么知道。

## Answer

学习者的选择：
- **定时载体**：用 Claude 桌面 App 自带的「定时任务」，每天跑一次。Mac 睡眠或 App 没开的那天就不跑。每份计划至少排够 7 天，偶尔漏跑不会断粮。不用 launchd 加 `claude -p`，也不用云端定时任务。
- **失败怎么知道**：有两层提醒。
  - 桌面 App 自带运行记录和失败通知。
  - App「学习」标签在以下两种情况显示一行黄字「学习计划 N 天未更新，去检查选词规划」：最新计划的 `generated_at` 超过 3 天，或剩余可用新词不够 2 天。平时不显示。这层兜住所有停跑原因：Mac 没开、凭据失效、校验没过。
- **手动运行**：在 Mac 上的 Claude Code 里输入 `/word-plan`，后面可以带一句临时要求（如 `/word-plan 这周出差，少排点`）。skill 不追问，直接出计划；这句要求原样记进计划文件。定时运行和手动运行走同一条路径。
- **选词说明**：中文，每条不超过 40 字，只写三类内容：
  - 为什么现在学（如"测试答错且高频""复习常评模糊"）；
  - 易混词；
  - 记忆提示。

  不重复词典释义和例句，那些已在卡片上。不确定的事不写，不编造词义和词源。
- **选词优先级**：
  1. 「想学」记录的词，必须排进计划，放最前；
  2. 似懂非懂的词：测试中 P 在 0.3–0.7，或复习里「模糊」偏多；同等情况下高频优先；
  3. 其余 Target 词，按词频排。

  Claude 可以偏离这个顺序，但要在该词的选词说明里写明理由。易混词（如 affect/effect）不排在同一天，至少间隔几天。
- **`focus_targets`（≤50）**：意思是"学习者眼下正在攻的词"。
  - 先放正在学、还没掌握的卡片，近期答错或评「模糊」多的排前面；
  - 不够 50 个，再用计划中接下来几天的新词补满。
- **每次的中文摘要**：每次运行写 1–3 句中文摘要（如"本期排 70 词，复习积压较多，每天建议 8 个；优先补测试中答错的高频词"）。摘要写进计划文件和提交说明，并显示在 App「学习」标签的新卡数下方。

实现细节（agent 决定）：
- **skill 的位置**：放在 `english-data` 仓库的 `.claude/skills/word-plan/`，和数据一起管版本。定时任务的工作目录是 Mac 上本地 clone 的 `english-data`，提交用 Mac 上已有的 git 凭据（SSH 或 `gh`）。iPhone 和 Actions 的 PAT 不变，也不共用。
- **输入：先汇总再给 Claude**：skill 自带一个汇总脚本，读全部 `observations/`、最新的 `words.tsv`、上一份计划、`source: setting` / `source: wish` 记录，输出一份精简摘要。Claude 只读这份摘要，不读原始 JSONL，所以历史再长也不会撑满上下文。摘要包括：
  - 候选词池：未建卡的 Target 词，约 400 个，按上述优先级预分桶。每个词附 P、词频排名、测试作答历史、4 档评分计数；
  - 活跃卡片的近期表现：用于挑 `focus_targets`；
  - 未来 7 天的到期复习数：用于判断积压；
  - 顽固词清单；
  - 尚未排进计划的「想学」词；
  - 设置里的每日新词上限；
  - 上一份计划还剩多少没用。
- **每日建议数**：Claude 在设置上限内决定 `daily_new`，复习积压多就少排。
- **输出文件**：沿用「Target 词的选取与排序」定的 `plan/YYYY-MM-DD.json`，另加三个字段：
  - `schema_version`；
  - `summary`（中文摘要）；
  - `instruction`（手动运行时的临时要求，没有则为 null）。

  同一天重跑就覆盖当天的文件。
- **校验**：skill 自带一个校验脚本，检查以下各项：
  - JSON 合法，字段齐全；
  - `new_words` 的 lemma 都在词表里，不重复，不是已建卡、已 Mastered 或已评「太简单」的词；
  - 全部未排的「想学」词都已排进计划；
  - 条数 ≥ `daily_new × 7`（候选词池不够时例外）；
  - `focus_targets` ≤ 50；
  - 每条说明不超过 40 字。

  不合格时，Claude 按报错修改后重新校验，最多 2 次；仍不合格就不提交，任务以失败结束，由桌面通知和 App 黄字提醒兜底。易混词间隔交给提示约束，不做机器校验。
- **提交流程**：运行前先 `git pull --rebase`；只 `git add` 本次写的 `plan/` 文件；提交说明的首行是摘要；push 被拒时先 rebase 再重试一次。
- **运行时间**：每天 07:30。
- 不新增 ADR：skill 的位置和定时方式都容易改，没有难以撤销的取舍。
