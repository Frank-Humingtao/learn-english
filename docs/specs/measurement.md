# 规格：准确的词汇测量

Status: ready-for-agent

依据：[ADR 0002](../adr/0002-measure-only-no-study-or-planning.md)、[调研：准确的词汇量测量](../research/07-accurate-vocab-measurement.md)、2026-11-13 的 grilling 结论，以及 [GLOSSARY.md](../../GLOSSARY.md)。同步、两个仓库和发布流水线沿用 [旧规格](english-learning-system.md) 和 [ADR 0001](../adr/0001-append-only-observations-and-two-repos.md)。

## Problem Statement

现有的 Vocabulary Test 测得不准，用起来也不舒服。

- **不准**：一次 17 分钟的 Baseline Test 测了 710 题，估计出 6385 个词族，但 95% 区间是 3326 到 9443。高频段之后的掌握率曲线太平：第 25 千词那一段还有 14% 的掌握率。只有 461 个词被判为 Mastered，Word Band 没法用。
- **不舒服**：
  - 基线测试长达 30 分钟；
  - 界面上到处是说明小字；
  - 答题没有反馈，也没有节奏感，测久了让人不耐烦。

Recommendation Agent 推荐内容的质量，取决于本系统逐词数据的准确度。

## Solution

1. **先建离线评测**：用已有的 Observation 和模拟学习者，算出一组固定的准确度指标。之后每次改模型，都先过这套评测。
2. **按评测结果重写模型**，按调研 07 的建议：
   - 认识和作答分成两层：猜测率不计入"认识"；
   - 难度由词特征回归得出，特征包括多来源词频、考纲标签等；
   - 输出逐词认识概率和标准误；
   - 总数分 ≤14k 和 >14k 两段报告。
3. **改测试流程**：
   - 基线测试不超过 15 分钟，短测不超过 10 分钟；
   - 当场核验答"认识"的词；
   - 选词按四种用途分配；
   - 答题时词汇量实时跳动；
   - 假词和释义题当场判对错。
4. **界面做到极简**：先做 HTML 原型给 Learner 看，再改 App。

Learner 在手机上实测后反馈，方案据此反复迭代。

## User Stories

1. 作为 Learner，我想在 15 分钟内做完 Baseline Test，10 分钟内做完一次短测，这样测试不会让我不耐烦。
2. 作为 Learner，我想答题时看到词汇量随作答实时跳动，这样测试有盼头。
3. 作为 Learner，我想对假词点了"认识"或释义题答错时，马上得到"错"的提示和音效，这样我会诚实作答。
4. 作为 Learner，我想每次作答都有触感、音效和翻卡动画，可以滑动或点按钮作答，这样测试更生动。
5. 作为 Learner，我想界面上没有说明性小字，只有数字、图表和按钮，详细内容都去看报告。
6. 作为 Learner，我想 App 只有三个标签：测试、进度、设置。
7. 作为 Learner，我想结果页只显示新的词汇量和较上次的变化；只有这次作答明显异常时，才多一行提示。
8. 作为 Learner，我想主屏有一个链接，直接打开最新的 Progress Report。
9. 作为 Learner，我想多次测试的证据能累积起来，估计越测越准，区间越测越窄。
10. 作为 Recommendation Agent，我想拿到逐词认识概率及其标准误、≤14k 和 >14k 两段词汇量、各频段掌握率，这样我能算出任意文本的 Coverage，并据此判断推荐内容的难度。
11. 作为维护者，我想每次改模型都能看到留出预测、校准、区间宽度和重测一致性这几个指标，这样我知道改动是变好还是变坏。

## Implementation Decisions

- **不接墨墨**：Observation 只来自 Vocabulary Test，包括 `test`、`spotcheck`、`verify` 三种。旧文件里的 `review` / `wish` / `setting` / `relearn` 一律忽略。
- **评测协议**（指标和初始阈值见[调研 07](../research/07-accurate-vocab-measurement.md) §E，之后按数据调整）：
  - 留出预测：log loss、Brier、AUC，目标 AUC ≥ .80；
  - 校准误差 ECE ≤ .05；
  - 总数区间半宽：基线测试后 ≤ ±20%，累积约 1000 个校正观测后 ≤ ±10%；
  - 折半一致性；
  - 重测一致性；
  - 对照基线是"只用词频"的模型。
- **模型**：
  - 两层结构：知识层 P_know(w) = σ(θ − b_w)；作答层用漏答率 s 和误报率 f，f 可以随词形熟悉度变化。
  - b_w = β·特征 + u_w，u_w 的方差从数据中估计。特征的维度要少，并加正则化。
  - 考纲标签按"最早出现的考试级别"编码，再用留出 log loss 检验它是否有用。
  - 四选一核验题自带猜测参数，和 Yes/No 作答进入同一个似然。
  - 场次层面的质量门槛：假词误认率超过 10%，或核验失败率异常时，该场降权，不直接丢弃。
- **测试流程**：
  - 基线测试约 450 道 Yes/No，短测约 300 道。
  - 伪词约占 15%，与真词的长度和拼写形态匹配。
  - 答"认识"后约 10% 当场追问中文四选一，带"不认识"选项。
  - 真词按用途分配：约 40% 分层抽样估总数，约 40% 选最不确定且常见的词，约 15% 选 P≈0.5 的词定水平，约 5% 复测旧词。
  - 核验过的词之后只当作"学习后"的证据。
  - 不加打字写释义的题。
  - 以上都是起点，具体数字由评测结果来调。
- **界面**：
  - 三个标签：测试、进度、设置。
  - 进度页保留图表，去掉说明小字。
  - 设置页只有令牌、同步状态、重做基线测试。
  - 同步状态只在出错时显示。
- **发布**：沿用 `english-profile` 和 Progress Report issue。新增 ≤14k / >14k 两段总数，`words.tsv` 增加标准误，`schema_version` 升到 3。

## Testing Decisions

- 主要测试接缝是离线评测本身。模型的单元测试只测对外行为：单调性、校准、模拟学习者的真实值落在区间内、重测一致性。
- 用"已知真实知识状态"的模拟学习者做端到端检验，包括会虚报的模拟学习者。
- App 和 Actions 的结果一致性测试（AppParityTests）、发布流水线的 dry-run 测试照常保留。

## Out of Scope

- 背单词、选词规划、内容推荐、读取墨墨数据。
- 打字写释义的题，以及任何需要 AI 判分的题型。

## Further Notes

- 答题时实时显示词汇量，可能诱导 Learner 多点"认识"。评测时要关注假词误认率和核验失败率是否上升，一旦上升，把数据拿给 Learner 看，再决定是否调整。
- 调研 07 的"未核实与开放问题"一节，列出了几篇只核对到二手资料的文献。
